**2. B1 공격 경로 상세 — 정적 분석**

기존 공격에 대한 개선은 실질적입니다. 어댑터가 ref 채점기를 덮어쓴 뒤 종료하면 재해시에서 차단되고, 그 변경을 되돌리더라도 이미 저장한 원래 바이트를 사용하므로 그 교체만으로 채점을 속이지는 못합니다.

그러나 다음 경로는 남습니다.

| 공격 경로 | 판단 |
|---|---|
| **실행용 `pe-grader-*` 파일 교체** | 저장한 바이트를 디스크에 쓰고 나서 Python이 경로를 다시 엽니다. 살아남은 동권한 프로세스가 이 사이에 파일을 교체할 수 있습니다. 이 디렉터리는 `assets_digest()` 대상 밖이며 실제 실행 파일의 사후 비교도 없습니다. 기록되는 해시는 원래 `blob`의 해시입니다. `pe.py:585`, `:598`, `:608`. |
| **snapshot·case·Evidence 경쟁** | snapshot은 경로로 전달되고, Evidence는 검증·메모리 저장 후 동일한 `stdout.json` 경로를 채점기에 전달합니다. 채점 순간 내용을 바꾸고 복원하면 검증·보존한 증거와 채점한 증거가 달라질 수 있습니다. `pe.py:596`, `:839`, `:849`, `:859`. |
| **Python 환경 변조** | **경쟁이나 `setsid` 없이도 가능한 조건부 경로**입니다. 평가기가 쓰는 venv 등의 site-packages에 어댑터가 쓰기 가능하면, 첫 실제 채점 전에 `.pth`·`sitecustomize` 시작 코드를 심을 수 있습니다. 이후 새 Python 채점기 프로세스가 시작할 때 종료 코드 0을 반환하도록 만들면 원래 채점기를 실행하지 않고 PASS가 됩니다. `-I`는 `-S`가 아닙니다. 실행 명령은 `pe.py:592`, 환경 필터는 `:568`이며 Python 설치 무결성 검사는 없습니다. |
| **결과 쓰기 직전·직후 변경** | 최종 자산 검사는 `finish()` 전에 끝납니다. 기록을 읽어 확인한 뒤 변경하거나 `result.json`을 덮어쓰는 것을 막지 못합니다. `pe.py:1072`, `:783`, `:1146`. 해시와 파일을 같은 공격자가 함께 수정할 수 있으므로 해시는 독립적인 신뢰 근거가 아닙니다. |
| **`pe.py` 자체 변경** | 실행 중 디스크의 `pe.py`만 바꿔도 이미 로드된 함수가 즉시 바뀌지는 않습니다. 따라서 이것만으로 현재 판정 위조가 된다고 단정하면 안 됩니다. 다만 시작 시 한 번만 비교하고 재해시 대상에서 제외하므로 이후 변조는 탐지하지 않습니다. 다음 실행 및 외부 소비자의 신뢰 문제는 남습니다. `pe.py:998`, `:403`. |

Python 시작 환경에 대해서는 파일 쓰기 없는 실행으로 `python3 -I`의 `isolated=1`, **`no_site=0`**을 확인했습니다. 실제 악성 `.pth` 설치나 trusted PASS 위조까지 실행한 것은 아닙니다.

따라서 “시작 시 읽은 바이트를 사용한다”는 개선은 맞지만, **그 바이트가 실제 채점 프로세스에서 실행됐음을 보장하지는 않습니다.** 같은 사용자에게서 생성한 임시 디렉터리는 권한 격리가 아닙니다.

**3. 새 결함·회귀**

다음은 이번 변경에서 생겼거나 새 보장과 직접 충돌하는 항목입니다. 모두 정적 분석입니다.

- **중간 — 오류로 중단된 실행의 이전 trial 기록이 소실됩니다.**  
  기록을 메모리에만 보관하도록 바꿨지만, `cmd_gate`의 예외 경로는 `result.json`만 씁니다. 예를 들어 첫 trial이 끝난 뒤 다음 trial에서 자산 변조나 grader 오류가 발생하면 이미 끝난 trial의 기록·증거도 저장되지 않습니다. 공격을 탐지한 실행에서 감사 자료가 사라지는 회귀입니다.  
  근거: `skills/portable-eval/scripts/pe.py:765`, `:858`, `:1079`, `:1134`.

- **중간 — manifest의 변조된 내용을 정상 해시로 기록할 수 있습니다.**  
  manifest를 쓴 뒤 다시 읽기는 하지만, 읽은 내용을 의도한 직렬화 결과와 비교하지 않고 그 해시를 그대로 채택합니다. 그 사이 바뀐 내용도 인증된 것처럼 기록될 수 있습니다. 또한 `result.json`은 다시 읽거나 해시를 기록하지 않는데, 계약은 result까지 읽어 확인하고 해시를 남긴다고 서술합니다.  
  근거: `skills/portable-eval/scripts/pe.py:1140`, `:1146`; `skills/portable-eval/docs/contracts.md:24`.

- **낮음 — `exec` grader의 실행 권한 요구가 사라졌습니다.**  
  원본 실행 비트를 확인하던 코드를 제거하고 사본에 무조건 `0700`을 부여합니다. 이제 실행 불가능한 원본도 실행될 수 있어 계약과 다릅니다.  
  근거: `skills/portable-eval/scripts/pe.py:591`; `skills/portable-eval/docs/contracts.md:83`.

별도로, **B7 잔여 결함은 실행 재현했습니다.** 정상 Evidence의 `final_state`에 `"overflow": 1e999`를 넣으면 `loads_strict()` 결과는 `inf`, 실제 Evidence 스키마 검증 결과는 `[]`입니다. `1e999` 자체는 JSON 숫자 문법에 맞지만, 파싱 후 비유한수가 되는 경우를 처리하지 않습니다. 자유 형식 필드도 포함해 검사하거나, 숫자 표현을 보존하는 처리가 필요합니다. 근거는 `pe.py:89`, `:191` 및 `skills/portable-eval/schemas/evidence.schema.json:8`입니다.

**5. 14.3절의 남은 한계 평가와 릴리스 조건**

14.3절은 **방향은 정확하지만 충분하지 않습니다.** 동권한 경쟁, 미실행 환경, `UNSET` 핀을 명시한 점은 적절합니다. 그러나 다음을 보완해야 합니다.

1. **경쟁 없는 Python 환경 공격**도 포함해야 합니다. 보호 대상은 ref 자산뿐 아니라 Python 실행 파일·라이브러리·site-packages, 실행용 임시 파일, 증거·결과 저장소까지입니다.
